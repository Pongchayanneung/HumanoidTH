Date: 2026-11-05 (Asia/Bangkok). Product revision: `4889cc2`; acceptance-test integration: `a9af90c`; screenshot timing refinement: `c97aeb4` (focused mobile rerun passed). Later documentation edits do not change the tested product implementation.

## Delivered behavior

One explicitly configured operator signs in with a PostgreSQL-backed opaque session. Multiple browsers are independent; logout invalidates copied tokens for that session. Four-hour absolute expiry, central configuration rotation/global revocation, shared login admission limits, bounded scrypt work, cookie attributes and same-origin checks are implemented. Legacy users, simulated roles, old identity cookies and Basic credentials confer no authority.

The administrator landing shows session status only. Account registration/history, submissions, CMS inspection/editing/review/publication, ingestion, CSV export and map analysis/cache work remain unavailable at the server and UI. Public discovery/language navigation remain usable. Inspection (#8), public projections (#5), honest map behavior (#6) and other baseline work have separate acceptance gates.

## Review and failures resolved

Task implementers used Sol at medium/high effort; the documentation draft used Luna. The primary agent reviewed/integrated exclusive-file tasks. When several workers hit an account usage limit, the primary completed the bounded fixes and remaining test runs; a separate GPT-6 Sol reviewer subsequently checked those fixes and the acceptance diff. See the retained [independent review](2026-11-05-issue-4-review.md).

- Real-handler regression tests failed against the old role simulation/mutation paths before the server denials were implemented.
- The shared password-hash loader initially differed from Next's dollar-sign expansion. It now uses the official Next environment loader with escaped `.env` parity tests.
- Terminal input initially mishandled split UTF-8 buffers. A failing Thai/emoji regression preceded the StringDecoder fix.
- Source review found inherited login-error keys crashing the page and missing Prisma assets in route-specific login traces. Own-property selection and explicit output tracing pass component and built-artifact regressions.
- The first actual browser run exposed CommonJS/default-import differences in Next's bundle, producing deliberate authentication-unavailable responses. Cross-runtime export normalization fixed it; the same browser login/session suite then passed.
- A test selector initially matched both the error alert and Next's route announcer. Scoping to the actual error element resolved the harness ambiguity.
- Sandbox/localhost restrictions and a missing matching Chromium were runtime prerequisites, resolved without changing the app's framework versions. Only `server-only` and the already-used matching `@next/env` helper were added as direct dependencies.
