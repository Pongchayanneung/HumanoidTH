# Hack Day planning

The team plans baseline repairs and Atlas Search in separate work allocations.

| Plan | Scope |
| --- | --- |
| [Hack Day fix plan](hack-day-fix-plan.md) | Three developers, 5–6 hours: six committed baseline outcomes, eight must-do repair packages, conditional extensions and release checks. |
| [Feature implementation Hack Day plan](feature-implementation-hack-day-plan.md) | Three developers, six feature hours: public atlas-wide Thai–English search, keyword and semantic retrieval, original evidence, evaluation and a deployed demonstration. |

The [baseline audits](../Baseline-audit/README.md) explain the findings behind the repairs. The [feature description and motivation](../feature-description-and-motivation.md) explains the search proposal and its expected benefits. The [feature technical design](../feature-technical-design.md) details the architecture and data rules used by the feature plan.

Before implementation, reconcile the fix plan's earlier feature assumptions with the atlas-wide search plan. Record the actual starting revision, working environment and agreed allocation. Report passed, failed and unrun checks at handoff.
