# Hero feature: Readiness Search

## สรุปใน 1 ประโยค

ระบบค้นหางานวิจัย โค้ด และหุ่นยนต์ด้วยความหมายในที่เดียว แล้วบอกตรงๆ ว่าข้อมูลส่วนไหนยังไม่รู้ก่อนที่นักวิจัยจะตัดสินใจหยิบไปใช้


## ปัญหา

ฐานข้อมูลมีทั้งหมด 6,749 รายการ แต่แยกกระจัดกระจายกันอยู่และมีข้อมูลขาดหายต่างกัน:

| ประเภทข้อมูล | จำนวนรายการ |
| --- | --- |
| เปเปอร์งานวิจัย | 3,548 |
| GitHub repo (คลังเก็บโค้ดบนเว็บ GitHub) | 2,659 |
| วิดีโอ | 327 |
| หุ่นยนต์ | ราว 40 |

เมื่อนักวิจัยตั้งคำถามว่า "งาน social robot สำหรับผู้สูงอายุ มี repo ไหนใช้ต่อได้" จึงต้องเปิดหลายแท็บเพื่อเทียบข้อมูลเอง และระบบเดิมไม่เตือนว่าข้อมูลส่วนไหนหายไป เช่น เปเปอร์ถูกตัด abstract (บทคัดย่อของงานวิจัย) ทิ้ง และ repo ไม่มีเวอร์ชันของ ROS (ระบบซอฟต์แวร์สำหรับควบคุมหุ่นยนต์)

กลุ่มผู้ใช้เป้าหมายคือนักวิจัยและนักศึกษาด้าน HRI (Human-Robot Interaction หรือการศึกษาปฏิสัมพันธ์ระหว่างมนุษย์กับหุ่นยนต์) ทั้งนี้ระบบยังไม่ได้ทดสอบกับคนจริง ปัญหานี้จึงยังเป็นสมมติฐาน

## ผู้ใช้ทำอะไร

1. **ค้น**: พิมพ์โจทย์ที่ต้องการด้วยภาษาปกติ ระบบจะใช้ semantic search (การค้นหาด้วยความหมาย) เพื่อรวมทั้งเปเปอร์, GitHub repo และหุ่นยนต์ที่เกี่ยวข้องมาไว้ในหน้าเดียว
   *ตัวอย่าง*: พิมพ์คำว่า `"social robot elderly"` แล้วได้รายการเปเปอร์ดูแลผู้สูงอายุคู่กับคลังโค้ดหุ่นยนต์ที่เกี่ยวข้องทันที
2. **เลือกและเทียบ**: กดเลือก 2-3 รายการที่สนใจเข้าสู่ตาราง Readiness (Readiness table หรือตารางเทียบความพร้อมใช้งาน) ช่องที่มีหลักฐานจากต้นทาง เช่น license (สัญญาอนุญาตใช้งาน) และ sourceUrl (ลิงก์ไปยังหน้าเว็บต้นทาง) จะแสดงตามจริง ส่วนช่องที่ไม่มีข้อมูลจะแสดงเป็น `unknown` (ไม่ระบุเพราะไม่มีข้อมูลยืนยัน) โดยไม่ขึ้นสีเขียวและไม่ใช้คำว่า compatible (เข้ากันได้) ไปเอง
   *ตัวอย่าง*: เทียบ 2 repo แล้วเห็นชัดว่าตัวแรกมี `license` แต่ช่องเวอร์ชัน ROS ขึ้นว่า `unknown`
3. **บันทึกและส่งต่อ**: พิมพ์เหตุผลที่เลือกหรือตัดออก พร้อมระบุ next action (สิ่งที่ต้องทำต่อ) 1 บรรทัด ผู้ใช้สามารถปิดแท็บแล้วกลับมาทำต่อได้ และสั่ง export (ส่งออกข้อมูลเป็นไฟล์) เป็น `decision-brief.json` หรือ `.md` เพื่อส่งให้ทีมได้
   *ตัวอย่าง*: จดบันทึกว่า `"เลือก repo นี้ไว้ก่อน แต่ต้องทักถามผู้เขียนเรื่องเวอร์ชัน ROS"` แล้วกดส่งออกไฟล์ `.md`

## ทำงานยังไง

- ระบบสร้าง embedding (ชุดตัวเลขแทนความหมายของข้อความ) ไว้ล่วงหน้านอกเว็บด้วยโมเดล Qwen3-Embedding 0.6B (โมเดล AI แปลงข้อความเป็นตัวเลขขนาด 1024 มิติ) แล้วบันทึกเป็นไฟล์หรือตาราง index (ดัชนีสำหรับค้นหาข้อมูล)
- ในจังหวะที่ผู้ใช้กดค้นหา หาก query API (ระบบแปลงคำค้นของผู้ใช้เป็นเวกเตอร์สด) ใช้งานไม่ได้ ระบบจะค้นด้วย keyword search (การค้นหาจากคำที่สะกดตรงกัน) ก่อน จากนั้นนำเวกเตอร์ (vector หรือชุดตัวเลขแทนความหมาย) ที่คำนวณไว้แล้วมาขยายผลลัพธ์ที่ใกล้เคียง พร้อมแสดงแบนเนอร์บอกสถานะบนหน้าจอตรงๆ โดยไม่แอบใช้ข้อมูลปลอม
- ระบบยังไม่ใช้ Gemini API (บริการเชื่อมต่อโมเดล AI ของ Google) แบบเสียเงิน

## ต่างจากเครื่องมือที่มีอยู่ยังไง

- เครื่องมือที่มีอยู่อย่าง Zotero, Elicit, Litmaps และ ROS Index ต่างทำงานเฉพาะส่วนของตัวเอง แต่ไม่ได้เชื่อมเปเปอร์, GitHub repo และหุ่นยนต์เข้าด้วยกันในหน้าเดียว ทั้งนี้ข้อเปรียบเทียบนี้ยังไม่ได้ทดลองเทียบจริง จึงมีสถานะเป็น UNPROVEN (ยังไม่ได้พิสูจน์ด้วยการทดสอบจริง)

## เกณฑ์ผ่าน

ทุกข้อด้านล่างต้องรันทดสอบได้จริง:

1. ค้นคำว่า `"social robot elderly"` แล้วได้ผลลัพธ์จากฐานข้อมูลจริงทั้งเปเปอร์และ GitHub repo พร้อมแสดงโหมดการค้นหาที่ใช้จริงบนหน้าจอ
2. ช่องข้อมูลที่ฐานข้อมูลไม่มี ต้องแสดงคำว่า `unknown` ทุกช่อง
3. เมื่อกดบันทึกแล้ว reload (โหลดหน้าเว็บซ้ำ) รายการที่เลือก, สถานะ, เหตุผล และ `sourceUrl` ต้องยังอยู่ครบ
4. เมื่อสั่ง Export (ส่งออกไฟล์) แล้ว Import (นำไฟล์กลับเข้าระบบ) ข้อมูลต้องตรงกับของเดิม และรายการที่ข้อมูลต้นทางหายไปต้องแสดงสถานะว่า `missing source` (ไม่พบข้อมูลต้นทาง)
5. ถ้าเขียนข้อมูลลง `localStorage` (พื้นที่เก็บข้อมูลในเบราว์เซอร์ของผู้ใช้) ไม่ได้ ระบบต้องแสดง error (ข้อความแจ้งข้อผิดพลาด) และห้ามแสดงคำว่า `Saved` (บันทึกสำเร็จ)

## ข้อจำกัดที่ทราบ

- **ขอบเขตข้อมูลสาธารณะ**: หน้าค้นหาต้องส่งเฉพาะข้อมูลสาธารณะ (public-only) โดยกรองที่ฝั่ง server (เครื่องแม่ข่าย) ก่อนเปิดใช้งาน
- **ID (รหัสประจำตัวรายการ) ไม่เสถียร**: ต้องบันทึกรหัส record ID คู่กับ `sourceUrl` เสมอ ห้ามอ้างอิงข้อมูลจากลำดับแถวในตาราง
- **abstract ของฐานข้อมูล OpenAlex ถูกตัดทิ้ง** (อยู่ที่โค้ดไฟล์ `lib/ingest/adapters.ts:21`): ทำให้เวกเตอร์ของเปเปอร์จำนวนมากมาจากชื่อเรื่องเพียงอย่างเดียวจากฐานข้อมูล OpenAlex (คลังข้อมูลงานวิจัยเปิดระดับโลก) ระบบจึงต้องแจ้งข้อจำกัดนี้ให้ผู้ใช้เห็นบนหน้าจอ

## คำศัพท์

- **embedding / Qwen3-Embedding**: เทคนิคและชื่อโมเดล AI ที่ใช้แปลงข้อความให้กลายเป็นชุดตัวเลข เพื่อใช้คำนวณว่าข้อความไหนมีความหมายใกล้เคียงกัน
- **vector / เวกเตอร์**: ชุดตัวเลขที่ได้จากการแปลงข้อความ ใช้เป็นพิกัดสำหรับเปรียบเทียบความใกล้เคียงของความหมาย
- **semantic search**: การค้นหาจากความหมายและบริบทของคำถาม แม้คำในผลลัพธ์จะไม่ได้สะกดตรงกับคำค้นเป๊ะๆ ก็ตาม
- **keyword search**: การค้นหาแบบดั้งเดิมที่ดูเฉพาะคำที่สะกดตรงกับคำค้นหาเท่านั้น
- **localStorage**: พื้นที่เก็บข้อมูลขนาดเล็กที่อยู่ในเว็บเบราว์เซอร์ของผู้ใช้ ทำให้ปิดแท็บแล้วเปิดใหม่ข้อมูลยังอยู่
- **sourceUrl**: ลิงก์เว็บไซต์ต้นทางของเปเปอร์ โค้ด หรือหุ่นยนต์รายการนั้น สำหรับกดไปตรวจสอบข้อมูลจริง
- **`unknown`**: ป้ายกำกับในตารางที่ใช้บอกตรงๆ ว่ายังไม่มีข้อมูลยืนยันจากต้นทาง เพื่อไม่ให้ระบบเดาคำตอบเอง
- **Readiness table**: ตารางเปรียบเทียบความพร้อมของเปเปอร์ โค้ด และหุ่นยนต์ 2-3 รายการที่ผู้ใช้นำมาวางเทียบกันก่อนตัดสินใจเลือกใช้
- **query API**: ช่องทางเชื่อมต่อสำหรับส่งคำค้นหาของผู้ใช้ไปแปลงเป็นเวกเตอร์แบบสดๆ ในจังหวะที่กดค้นหา
- **UNPROVEN**: ข้อสังเกตหรือสมมติฐานที่ฟังดูมีเหตุผล แต่ยังไม่ได้ลงมือทดสอบหรือวัดผลเปรียบเทียบจริง
- **OpenAlex**: ฐานข้อมูลออนไลน์แบบเปิดที่รวบรวมรายชื่อและข้อมูลงานวิจัยจากทั่วโลก
- **abstract**: บทคัดย่อสั้นๆ หน้าแรกของงานวิจัยที่สรุปว่างานชิ้นนั้นทำอะไรและได้ผลอย่างไร
- **ROS**: ระบบซอฟต์แวร์มาตรฐานที่นักพัฒนาใช้เขียนโปรแกรมควบคุมการทำงานของหุ่นยนต์
- **HRI**: สาขาวิชาที่ศึกษาการออกแบบและทำงานร่วมกันระหว่างมนุษย์กับหุ่นยนต์ (Human-Robot Interaction)
